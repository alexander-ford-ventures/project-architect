# project-architect v2.3 — Programming Language project type

> **Status:** PLANNED (2026-05-13). Not yet executed. Execution per `superpowers:subagent-driven-development` against this plan, following the workflow rules in `/CLAUDE.md` (TDD, opus + max-effort, combined-review + parallel-dispatch, release commit must be last).
>
> **Ecosystem research dated 2026-05-13:** plan content reflects LLVM 22.x stable, Java 25 LTS, GraalVM 24/25 LTS, Wasm 3.0 (W3C standard since Sept 2025: WasmGC + EH + tail calls + multi-memory + memory64 + SIMD all shipped), WASI 0.2 stable / 0.3 RC, Python 3.14 (no-GIL opt-in not default + experimental JIT), OCaml 5.4 (effect handlers production but still "experimental"), Lean 4 + Mathlib4 (>210K theorems), Koka 3.2.3, Gleam 1.16. Versions WILL drift — future revisions of this plan should re-research.

**Goal:** Add `programming_language` as a first-class project sub_type with 6 dedicated design templates, new state.decisions for implementation strategy / paradigm / type-system / host-runtime, and the Phase 1-3 questioning paths to drive them. Lets a user run `/skill project-architect:project-architect` for "design a new programming language" and get a coherent doc set covering grammar, semantics, type system, stdlib, toolchain, bootstrap trajectory, and stability/RFC process.

**Scope (firm):**
- 6 sub_type variants of `programming_language`: `general_purpose_language`, `domain_specific_language`, `query_language`, `configuration_language`, `educational_language`, `transpiler_target`.
- 6 new templates (one Top template that gates the project as a PL design, dropped — see "Out of scope" — and 6 concern-specific templates listed below).
- 4 new state.decisions axes: `impl_strategy`, `host_runtime`, `paradigm`, `type_system`.
- Phase 1 routing question + Phase 2 implementation-strategy batch + Phase 3 type-system/paradigm batch.
- tech-stack-options.md gains a "PL implementation backends" table.
- 2 e2e fixtures (tree-walking interpreter Rust-impl + transpiler-to-JS DSL).
- Catalog registration + README "supported types" refresh.
- v2.3.0 release commit per CLAUDE.md release workflow.

**Out of scope (v2.3, may revisit in v2.4):**
- New auditor checks specific to PL design (e.g. "grammar tokens referenced in semantics must match"). Existing 16 checks cover link integrity / placeholders / yaml / etc.; PL-specific lint can come later if patterns emerge.
- Markup language sub_type (HTML/LaTeX/Markdown-class) — arguably outside PL design; users can pick a closer existing match.
- Multi-language toolchain integration (Rust+Python polyglot stdlib design). Stays single-language for v2.3.

**Tech stack:** Same as v2.2 — Markdown templates with YAML frontmatter, Bash + Python test scripts, `jq`/`shellcheck` for validation. No new tooling required.

**Conventions to follow** (codified in `/CLAUDE.md`):
- TDD: failing test first, then impl, then passing test, then `bash tests/run_all.sh`, then commit.
- Subagent-driven-development with opus + max-effort.
- File attribution: HTML header + footer on every new `.md`; 3-line bash-comment header on every new `.sh`.
- Release workflow: release commit must be the LAST commit before the v2.3.0 tag. No orphan post-tag commits.
